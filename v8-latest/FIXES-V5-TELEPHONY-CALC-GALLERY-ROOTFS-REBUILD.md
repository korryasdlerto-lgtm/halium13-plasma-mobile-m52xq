## Телефония (plasma-dialer v6.5.6)

### Находка 1: точные версии файлов в CMake Targets.cmake

`-dev`-пакеты 6.26.0-генерации ссылаются в своих `KF6*Targets.cmake` на
рантайм-библиотеку по ТОЧНОМУ имени файла (например
`libKF6I18n.so.6.26.0`), а на образе стоит `libKF6I18n.so.6.23.0`. Линковщику
всё равно (он смотрит только на SONAME `.so.6`), но CMake на этапе
`configure` физически проверяет существование файла с точным именем.

**Фикс**: `gen-compat-symlinks.sh` — для каждой реальной `libKF6*.so.<ver>`
добавляет симлинк `libKF6*.so.6.26.0 -> libKF6*.so.<реальная версия>`.
Создано 75 симлинков.

### Находка 2: `find_package(... 6.26.0)` compatible-version проверка

Отдельно от находки 1: CMake считает пакет совместимым только если
`ConfigVersion.cmake` заявляет версию `>=` запрошенной. Установленные
`KF6*ConfigVersion.cmake` (от 6.23.0-dev пакетов) заявляют `"6.23.0"` —
ниже требуемой 6.26.0, проверка `find_package(KF6Codecs 6.26.0)` не
проходит (см. цепочку `KF6Contacts→find_dependency(KF6Codecs 6.26.0)`).

**Фикс**: во всех 38 `KF6*/KF6*ConfigVersion.cmake` на образе строка
`set(PACKAGE_VERSION "X.Y.Z")` заменена на `set(PACKAGE_VERSION "6.26.0")`.
Это чисто метаданные для CMake (файл использует `write_basic_package_
version_file` в режиме AnyNewerVersion) — не влияет ни на dpkg, ни на
реальный ABI, ни на include-заголовки. Безопасно и обратимо.

### Находка 3: реально отсутствующие рантайм-библиотеки

Помимо заголовков, для части модулей не было вообще никакого рантайма
(не было даже в 6.23.0) — докачаны как новые `.so` файлы (не заменяя
ничего): `libKF6Contacts`, `libKF6People`, `libKF6PeopleBackend`,
`libKF6PeopleWidgets` (все 6.26.0), плюс Qt6Multimedia-стек и `qt6-svg-dev`.

### Статус на момент записи

Собрано и исправлено 3 итерации сборки (build.log каждый раз явно
проверялся — exit code внешней docker-обёртки НЕ гарантирует успех chroot-
скрипта, скрипт сам не пробрасывает код возврата наружу). Последняя

## Калькулятор (kalk) и галерея (koko) — оказалось намного проще

Оба — **готовые предсобранные пакеты** в репозитории droidian
(`kalk` 26.04.0-1, `koko` 26.04.0-1), сборка из исходников НЕ требуется.
Их зависимости на KF6 указаны как простое `>= 6.8.0` / `>= 6.20` —
обычная проверка `dpkg`, а не строгая CMake compatible-version проверка
(та актуальна только при СБОРКЕ из исходников через cmake, не при установке
готового `.deb`).

`kalk` — все зависимости уже были на образе, установился сразу.

`koko` потребовал докачать 12 недостающих пакетов (обычным `dpkg -i`, БЕЗ
`apt-get`, чтобы не спровоцировать апгрейд-каскад):
`koko-data` (Architecture: all — отдельный индекс `binary-all`, не
`binary-arm64`), `libkquickimageeditor1`, `qml6-module-org-kde-
kquickimageeditor`, `libopencv-core410`, `libopencv-imgproc410`, `libblas3`,
`liblapack3`, `libtbb12`, `libtbbbind-2-5`, `libtbbmalloc2`, `libhwloc15`,
`libgfortran5`.

**Находка**: `libgfortran5` требует `gcc-16-base (= 16.1.0-3)` точным
совпадением, а на образе уже стоит другая сборка `gcc-16-base
16-20260425-1` (более поздний снапшот той же GCC 16 — ABI рантайма
стабилен в пределах мажорной версии, реальной несовместимости нет).
Установлен через `dpkg --force-depends -i` только для этого файла —
не апгрейд, не замена файлов, просто снятие излишне строгой строковой
проверки версии там, где совместимость архитектурно гарантирована.

**Результат**: оба пакета подтверждены `ii` в `dpkg -l` внутри рабочего
образа — калькулятор и галерея полностью установлены.

### Механизм доставки: инъекция, НЕ пересборка чанков

Выяснилось (и это теперь основной путь для всех дальнейших фиксов): в5's
`update-binary` уже монтирует `rootfs.img` как rw ext4 прямо во время
прошивки и делает `cp -a "$EXTRAS"/rootfs-files/. "$ROOTFS_MNT/"` — то есть
всё дерево `halium-extras/rootfs-files/` накатывается поверх образа при
каждой прошивке. Поэтому общие 12GB чанки `rootfs-chunks/*` трогать НЕ
нужно вообще — оба (в4-прошитое устройство и в5) продолжают использовать
тот же самый мастер-образ, а новые файлы едут отдельно через эту инъекцию.

**Важно**: проверено через `readelf -d` на всех новых бинарях — все
`NEEDED` записи ссылаются на SONAME (`libKF6I18n.so.6`), НЕ на точные
версии файлов. Значит компат-симлинки `.so.6.26.0` (находка 1) и
`ConfigVersion.cmake`-патчи (находка 2) были нужны только для СБОРКИ —
на устройство их тащить не нужно, они остаются только в
`rootfs-master-working.img` как строительные леса.

**Собран и уже скопирован в `в5/halium-extras/rootfs-files/`** (423 файла
итого, слияние без конфликтов с уже существующим деревом):
- Манифест `ninja install` для `plasma-dialer` (без `/usr/include` и `.a` —
  не нужны рантайму) — 92 файла.
- 4 реально отсутствовавшие KF6-библиотеки (Contacts/People/
  PeopleBackend/PeopleWidgets, по 3 файла каждая: `.so`/`.so.6`/
  `.so.6.26.0`) — подтверждены как реально NEEDED через `readelf` (кроме
  PeopleWidgets — не нашёл прямого потребителя, оставлен на всякий случай,
  вес незначителен).
- `kalk`+`koko`+12 их докачанных зависимостей — полный список файлов через
  `dpkg -L` на все 14 пакетов.
- Проверено и **сознательно исключено**: весь стек Qt6Multimedia (докачан
  был "на всякий случай" в самом начале, но `readelf` на все новые бинари
  подтвердил — реально ничем не используется, был бы мёртвым грузом).

**Грабли при сборке инъекции**: `dpkg -L <pkg>` перечисляет не только
файлы пакета, но и родительские директории (`/usr`, `/etc`, `/var` и
т.д.) как отдельные строки. Наивный `cp -a --parents` по каждой строке
списка скопировал ЭТИ директории рекурсивно целиком — то есть весь
`/usr`+`/etc`+`/var` образа (221 000 файлов, 8.6GB) вместо нужных ~300.
Исправлено: перед копированием каждый путь явно проверяется (`[ -f ]`
или `[ -L ]`) — если это директория, просто пропускаем (родительские
директории создаются автоматически через `cp -a --parents` для реальных
файлов).

**На будущее, при формировании реального flashable zip**: в собранном
дереве 20 символьных ссылок (KF6People*, tbb, opencv, blas/lapack,
hwloc, gfortran). TWRP-шный `unzip` не сохраняет symlink'и (см. находку
выше про `lxc-bridge-libs`) — эти 20 файлов потребуют такого же
ремонтного прохода в `update-binary`, когда дойдём до реальной прошивки.
Сейчас это не актуально: тестируем через прямой `adb push`, где симлинки
сохраняются нормально.

### Сборка milou v6.5.2

Тот же хирургический метод, что и для `plasma-dialer` (Docker+qemu-
aarch64-static chroot, `rootfs-master-working.img`), но сильно быстрее —
milou маленький (всего один плазмоид поиска). `CMakeLists.txt` на теге
v6.5.2 требует `KF6_MIN_VERSION 6.18.0`, `QT_MIN_VERSION 6.9.0` — полностью
удовлетворяется уже имеющимся стеком (та же ситуация, что с
`plasma-dialer`). Недостающий кусок — заголовки+cmake `KF6Runner`
(`libkf6runner-dev`, скачаны и застейджены точно так же, только headers,
рантайм 6.23.0 не трогали); компат-симлинк `libKF6Runner.so.6.26.0` уже
существовал с прошлого массового прохода (находка 1 выше). `KF6Svg` уже
был застейджен ранее для другой цели.

Скрипт: `rootfs-rebuild-6.7/build-milou.sh` (копия структуры
`build-plasma-dialer.sh`, клонирует `--branch v6.5.2 --depth 1`).
Собралось с ПЕРВОЙ попытки: `CMAKE_EXIT=0`, `NINJA_EXIT=0`,
`INSTALL_EXIT=0`. Результат — `qmldir` теперь объявляет все 4 типа:
`ResultDelegate`, `ResultsView`, `ResultsListViewDelegate`,
`ResultsListView`. `NEEDED` у нового `libmilou.so` — только
`libKF6Runner.so.6`/`libKF6ConfigCore.so.6`/Qt6Qml/Core (все уже есть в
базовом образе, доп. рантайм-библиотеки не нужны).

Протестировано вживую: заново собранные 8 файлов
(`ResultDelegate.qml`, `ResultsView.qml`, `ResultsListView.qml`,
`ResultsListViewDelegate.qml`, `libmilou.so`, `milou.qmltypes`, `qmldir`,
`kde-qmlmodule.version`) залиты через `adb push` + `mount -o loop,rw`
поверх `/data/rootfs.img` (телефон в TWRP), заменяя существующие файлы
пакета `milou` **напрямую, в обход `dpkg`** — `/var/lib/dpkg` живёт на
read-only overlay в рантайме, `dpkg -i`/`--force-depends` там физически
не может писать свою базу ("Файловая система доступна только для
чтения"), поэтому для ЛЮБОЙ живой правки существующего пакета (не
только новых файлов) единственный рабочий путь — прямая подмена файлов,
как уже делалось для `phoc`-даунгрейда и других live-патчей.

Те же 8 файлов скопированы в `в5/halium-extras/rootfs-files/usr/lib/
aarch64-linux-gnu/qt6/qml/org/kde/milou/` (перезаписывая исходные файлы
пакета `milou` — это единственное место в текущей инъекции, где мы
именно ЗАМЕНЯЕМ существующий файл, а не только добавляем новый).
