# в20: база в14 + 5 фиксов из в16

## Контекст
По явному запросу пользователя — взять в14 за основу (полный набор
приложений, включая игры, никакой чистки из в17-в19) и добавить
ровно 5 конкретных фиксов из в16, без остального (без чистки
приложений, без изменений в лок-скрин фиксах сверх того, что уже
было).

**Важная находка при подготовке**: папка `в14` на диске уже содержала
три лок-скрин фикса (`chgrp shadow`, `chmod kscreenlocker_greet`,
`HandlePowerKey=lock`) в `halium-container-autostart.sh` — они были
дописаны туда позже вечером (изначально прошитый на телефоне архив
в14 их не содержал, расхождение между файлами проекта и тем, что
реально было прошито). Поскольку пользователь не просил их убирать —
оставлены как есть.

## Фикс 1 — порядок операций в автозапуске контейнера
Блок проверки+remount,rw (`/` иногда поднимается ro из-за бага
initrd) стоял ПОСЛЕ трёх лок-скрин фиксов в `halium-container-
autostart.sh`. Раз лок-скрин фиксы уже были в в14, гонка (chmod
кscreenlocker_greet может тихо провалиться, если / ещё read-only в
этот момент) реально применима. Перенесён в самое начало скрипта, до
любой попытки менять `/etc`/`/usr`. Старый дублирующий блок перед
стартом контейнера убран.

## Фикс 2 — watchdog пробуждения экрана по кнопке питания
Новый `halium-power-wake-watchdog.service` +
`usr/libexec/halium-power-wake-watchdog.py`. Слушает
`/dev/input/event0` (qpnp_pon) на `KEY_POWER` press; если в момент
нажатия `dpms == "Off"` — перезапускает `plasma-mobile-wf.service`.
Не гадает по таймингам загрузки (в отличие от убранного в в12
`halium-plasma-shell-watchdog.sh`) — условие срабатывания это
измеримое состояние ядра плюс факт физического нажатия, ложных
срабатываний структурно быть не может. Enable-блок в update-binary
добавлен по тому же паттерну, что и `bluebinder.service`.

## Фикс 3 — `DISPLAY=:0` для SDL2-гонок
В в14 игровой стек (knights, gnuchess, extremetuxracer,
supertuxkart) ещё присутствует полностью (удалён только в в17) — этот
фикс тут особенно актуален. `extremetuxracer`/`supertuxkart` падали
при запуске с иконки с "Failed to open X11 display" (SDL2-сборки не
умеют в нативный Wayland, только через Xwayland). `Exec=` в обоих
`.desktop`-оверлеях дополнен `env DISPLAY=:0` — живьём подтверждено
рабочим в в16.

## Фикс 4 — обои DebianTheme→Next
`wallpaperplugin=org.kde.image` без явного `Image=` пытается открыть
несуществующий `DebianTheme` (пакета нет в образе), рабочий стол
рисуется серым. Добавлена функция `fix_wallpaper()` в
`startplasmamobile-wf` (новый оверлей-файл — в в14 такого оверлея не
было вообще, взята оригинальная структура скрипта без более поздних
изменений типа WAYLAND_DISPLAY-фикса из в15/в16, который сюда
намеренно НЕ переносился). Известное ограничение: первый запуск после
чистого /userdata покажет серый фон один раз, фикс применится со
второго запуска сессии.

## Фикс 5 — убрана мёртвая ссылка на flashlightd
`/usr/libexec/flashlightd` в `startplasmamobile-wf` — унаследовано из
Droidian вместе со всем скриптом, реального пакета с демоном тут
никогда не было. Убрано в том же новом оверлей-файле.

## Что НЕ переносилось из в16-в19 (намеренно)
- Импорт `WAYLAND_DISPLAY` в systemd `--user` (фикс powerdevil/
  яркости из в15/в16) — не входил в список 5 запрошенных фиксов.
- Чистка приложений (в17-в19) — в20 сохраняет полный набор
  приложений в14, включая игры.

## НЕ проверено живьём
Все 5 фиксов взяты дословно из уже проверенных живьём версий (в16),
но сама сборка в20 (база в14 + эти 5 фиксов вместе) — новая
комбинация, живьём ещё не тестировалась.
