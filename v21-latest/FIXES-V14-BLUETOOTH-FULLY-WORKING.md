# в14: Bluetooth полностью заработал (адрес + UI сопряжения)

## Контекст
Продолжение в13 (там появился сам демон `bluez`, но контроллер не
поднимался — "No default controller available").

## Проблема 1 — bluebinder_post.sh падал, MAC-адрес не выставлялся
`bluebinder.service`'s `ExecStartPost=/usr/bin/droid/bluebinder_post.sh`
падал с `status=1/FAILURE` на каждой загрузке. Причина — в самой
логике скрипта:
- `ro.bt.bdaddr_path` пуст на этом устройстве;
- `ro.vendor.bt.bdaddr_path` = `/mnt/vendor/efs/bluetooth/bt_addr` —
  путь, которого в этом halium-мосте попросту нет (efs-раздел не
  пробрасывается);
- скрипт (elif-цепочка) пробовал именно этот путь, `cp` падал,
  скрипт делал `exit 1` — и НИКОГДА не доходил до последнего
  фолбэка, `persist.vendor.service.bdroid.bdaddr`, а это свойство
  на самом деле содержит рабочий MAC (`22:22:35:02:c2:3e`,
  подтверждено `bluetoothctl show` после ручной правки).

### Что сделано
`usr/bin/droid/bluebinder_post.sh` переписан: property-based способ
(самый надёжный на этом устройстве) пробуется ПЕРВЫМ, path-based —
только как fallback, неудачный `cp` для них больше не фатален
(просто идём дальше по цепочке).

Также добавлен `usr/lib/systemd/system/bluebinder.service.d/
60-hybris-ld-path.conf` (`HYBRIS_LD_LIBRARY_PATH`+`ANDROID_ROOT`) —
не строго обязательно (сам скрипт уже делает `export` этой же
переменной), но для единообразия с остальными hybris-процессами
проекта (pulseaudio, plasma-mobile-wf) и как страховка на случай,
если что-то в будущем вызовет getprop до того, как скрипт успеет
сам её выставить.

**Проверено живьём НАПРЯМУЮ** (правка сначала протестирована на
живом в13 через `su`, потом перенесена в файлы): `bluetoothctl show`
после фикса показал полностью рабочий контроллер — `Powered: yes`,
весь список профилей (A2DP Sink/Source, AVRCP, Handsfree, GATT).

## Проблема 2 — не было UI для сопряжения устройств
`bluez` (демон) был, но `bluedevil` (модуль Настроек KDE + апплет
сопряжения) — не был установлен вообще. В Настройках не было раздела
"Bluetooth" в принципе, только переключатель вкл/выкл в шторке
(`org.kde.plasma.quicksetting.bluetooth`) без возможности что-либо
реально сопрячь.

### Что сделано
`apt-get install bluedevil` тем же chroot-методом. Подтянул
`plasma-nano`, `bluez-obexd`, обновление `kwin-wayland`/
`plasma-workspace` и evolution-data-server библиотеки (транзитивные
зависимости) — **проверено**: `plasma-mobile-wf` НЕ удалён, ничего
не помечено на удаление (`grep -i remove` по логу установки — пусто).

## НЕ проверено живьём
Обе правки внесены в `rootfs-master-working-clean.img` и
перенесены в новые чанки (`rootfs-chunks-v14`), но сам процесс
СОПРЯЖЕНИЯ с реальным внешним Bluetooth-устройством через
UI `bluedevil` ещё не тестировался — только то, что контроллер
поднимается и демон включён.
